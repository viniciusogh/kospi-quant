# 보고서 공식 실적 데이터 계약

`dart_earnings.Client.collect(code, asof)`가 수집하고 `report_earnings`가 같은 입력으로 본문과 표를 계산한다. `momentum_daily.main`의 실적 입력은 이 경로만 사용한다. KIS 시세·수급·재무비율 수집과는 별개다. 이 변경이 PER, ROE, 부채비율까지 공시 대조 완료로 승격시키지는 않는다.

## 수집과 대조

1. `corpCode.xml`에서 종목코드를 고유번호에 일대일 대응한다.
2. `list.json`의 A(정기)·I(거래소) 유형을 기준일 이전 550일 범위에서 각각 모든 페이지 조회한다. `last_reprt_at=N`으로 정정을 포함한다. 유형별 최대 1,000건을 넘거나 총수·기업·중복 검증이 실패하면 미확인 처리한다.
3. 가장 최근 보고 분기의 정기보고서와 이후 발표된 잠정 실적을 조사한다. 최신 잠정 공시의 양식을 못 읽으면 이전 정기 실적으로 대체하지 않는다. 더 오래된 분기에 대한 뒤늦은 잠정 공시도 현재 분기를 덮어쓰지 않는다.
4. 정기보고서는 `fnlttSinglAcntAll.json`과 `document.xml`의 본문을 대조한다. ZIP의 접수번호와 정확히 같은 XML만 본문으로 선택하여 감사보고서 첨부와 구별한다. API의 접수번호·기업·보고서코드·통화·계정이 일치해야 한다.
5. 연결 CFS 자료가 없다는 명시 응답 013일 때만 OFS를 조사한다. 통신 오류는 별도 기준으로 바꾸지 않는다.
6. 원문 재무표 바로 앞 표제의 손익계산서·연결 여부·원/천원/백만원 단위를 확인한다. 같은 계정과 기간이 있는 주석 표를 재무표 대신 읽지 않는다. 원으로 환산한 원문과 API 값이 정확하게 같아야 한다.
7. 잠정 실적은 표준 공시 본문의 당기·전년 동기 날짜, 단일분기, 열 배치, 단위를 검증해 추출한다. 정정 전후 요약표를 실적 표로 읽지 않는다. 원/천원/백만원/억원/조원을 지원한다.

## 기간 및 계산

매출 계정은 `ifrs-full_Revenue`, 영업이익은 `dart_OperatingIncomeLoss`다. 표준 계정이 없거나 여러 개면 미확인이다. 12월 결산사의 달력 분기를 지원한다.

정기 분기·반기 `thstrm_amount`와 `frmtrm_q_amount`는 3개월 수치다. 원문 컨텍스트는 Q1 `dFQQ`, Q2 `dHYQ`, Q3 `dTQQ`로 확인한다. 연간 `dFY`에서 3분기 누적 `dTQA`를 빼 4분기를 계산하며, 당기와 전년도 각각 동일 연도·연결 기준을 사용한다. API 누적 열과 원문의 누적 컨텍스트도 대조한다. 연간 값을 그대로 4분기로 표시하지 않는다. 서로 다른 보고서에서 얻은 누적 값이므로 재분류·재작성 여부까지 자동으로 전부 보장하는 것은 아니다.

금액 원본과 환산은 Decimal, 표시용 억원은 숫자로 보존한다. 전년 같은 분기 증감률과 영업이익률을 코드로 계산한다. 적자전환·흑자전환·적자 확대/축소는 음수 분모 성장률로 표시하지 않는다. 표시 정밀도는 본문과 표에서 동일하다.

## 표시 및 캐시

실적 아래에 출처·대상 분기·연결/별도·잠정/정기·정정·공시일·확인 기준일·실제 조회 시각을 항상 표시한다. 상세 원문 URL·접수번호·SHA256·숫자별 계산 근거는 추적용 데이터에 남긴다. 기준일 조회는 일자 단위이며, 과거 장 마감 시각까지의 실시간 가용성을 보장하는 백테스트 데이터가 아니다.

본문의 실적 결론·수치와 표는 동일 snapshot을 사용한다. 표는 확인된 당기와 전년 동기를 비교한다. 이전 한투 분기표는 현재 공식 실적과 혼합하지 않는다. 기존 원본 CSV/JSON을 이 작업에서 수정하거나 지우지 않는다.

분기·금액·접수번호·연결 기준·잠정·정정·원문 해시가 변하면 분석 캐시를 무효화한다. 단순 조회 시각 변경만으로는 무효화하지 않는다. 모델에 동일 실적을 전달하고 응답 기준 분기를 검사한다. 모델 실패로 구형 성장 설명을 되살리거나 전체분석일을 갱신하지 않는다. 모델의 사업 전망과 뉴스 해석은 여전히 별도 검토 대상이다.

## 실패와 운영

조회/해석/대조/기록 실패 시 실적은 `최신 실적 확인 중`이며 표를 비운다. 오래된 실적이나 KIS 값을 넣지 않는다. 별도로 수집한 시세와 수급은 계속 표시한다. 미지원 공시 양식이나 계정명은 임의 추정하지 않는다.

실행 근거는 gitignore된 `.recommendation_audits/earnings/`에 저장한다. API 키는 환경변수 `DART_API_KEY`에서만 읽고 응답 예외의 요청 URL은 출력하지 않는다. 로컬 .env는 기존 실행 환경 로더를 통해 사용한다. 모듈 자체가 임의 경로의 비밀키를 찾지는 않는다.

GitHub Actions에서는 `DART_API_KEY` repository secret이 필요하다. 로컬 .env 설정은 이 secret을 대신하지 않는다. hosted runner의 원문 감사 파일은 별도 보존 설정 없이는 실행 종료 후 유지되지 않는다. 분석 산출물에는 실적 출처와 원문 해시가 남지만 원문 파일 장기보관을 의미하지 않는다.

2026-09-26 로컬 구현 및 읽기 검증 완료. 후보 10개 정기보고서, 드림텍 Q1/Q4 계산, 삼성전자 정정 잠정 경로 확인. 최초 HTTP 403은 다른 GitHub 계정의 인증 때문이었다. 저장된 소유자 인증을 해당 작업 프로세스에만 적용해 관리 권한을 확인하고 DART_API_KEY repository secret을 등록했다. 기본 계정과 다른 프로젝트 인증은 변경하지 않았다. 배포 검증 진행 중이며 기존 Notion 보고서는 재게시하지 않았다.
