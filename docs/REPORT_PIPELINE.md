# 당일 마감 Report 준비 신호

2026-09-08: 고정 게시 시작 시각 대신 검증된 입력의 준비 완료를 게시 조건으로 사용한다.
보고서 데이터일은 마감일, 추천 대상일은 다음 거래일이다. 주문 경로와 독립적이다.

## 생산자

`Daily Quant Analysis`의 수급 → 섹터 → Quality → 모멘텀 두 변형 순서는 유지한다.
섹터 마감 모드는 기존 일봉 baseline + 현재가 중복 조회를 일봉 한 번으로 합친다.
4개 병렬 요청으로 기존 모멘텀과 같은 동시성 한도를 사용한다. 잠정 현재가를 종가로 쓰지 않는다.
`latest_sector_close.csv`는 로컬에서 자주 바뀌는 `sector_history.csv`와 분리한다.

기존 `sanity_check.py` 6개 산출물 게이트를 통과해야 한다. 추가로 `report_ready.py`는:

- 모멘텀 각 후보의 실제 일봉 `asof`와 수급의 실제 `기준일`을 검사한다.
- 당일 이력의 코드·종가와 추천을 대조하고, 부분 섹터 집계를 거부한다.
- 분석 JSON 읽기와 날짜를 검사한다. 오래된 장기 분석은 그 원래 날짜를 보존한다.
- 날짜·수집 시작/완료 시각·고정 파일 목록의 SHA256을 `report_inputs_ready.json`에 기록한다.
- 필요한 단계가 실패하면 표식을 만들지 않으며, 표식 push 실패도 비정상 종료한다.

당일 옛 CSV에 `asof`가 없다고 현재 날짜를 채우지 않는다. 새 스키마는 다음 정상 수집부터 적용된다.

## 게시자 계약

원격 준비 표식을 읽은 뒤 Git 동기화하고 로컬 파일 해시를 다시 검사한다.
수집 시작이 그날 **실제 정규장 종료 시각**보다 늦어야 한다. 15:30 고정 가정으로 늦게 닫는 날을 통과시키지 않는다.
당일 지수·후보 수급 필수 항목도 확인한 후 기존 Report 생성 경로를 한 번 호출한다.
완료된 날짜나 부분 생성된 날짜를 자동 재생성하지 않는다. 준비 전 상태와 생성 실패를 구분한다.

## 일정과 실측 한계

외부 cron-job.org 예약은 16:45 KST, GitHub 네이티브 백업은 17:30이다. 이 변경은 두 예약을 변경하지 않는다.
외부 예약 변경에는 해당 서비스 로그인이 필요하다. GitHub schedule은 지연될 수 있어 정시 보장 수단이 아니다.
실측 2026-09-08 수집은 55분, 이 중 섹터 약 9분 30초, Report 생성/게시 약 3분 22초였다.
새 섹터 전체 런 시간은 다음 운영 실행에서 측정해야 하며, 일부 종목 테스트를 전체 완료 실적으로 보고하지 않는다.

일반일 마감 직후 15:31부터 확인할 수 있지만, KIS 일별 투자자 데이터가 그 시각에 모두 확정된다는 보장은 없다.
당일 필수 자료가 실제로 확보되는 시점을 날짜/필수 필드로 확인해야 한다.
공식 KIS 설명도 제공 시점을 '장마감 이후'로 설명하며 정확한 분은 보장하지 않는다:
[공식 inquire-investor 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_investor/inquire_investor.py).
